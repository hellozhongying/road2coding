# 贡献规范

本文档用于记录 Zeus Spring Boot Framework 的协作约定。后续新增或调整项目规范时，需要同步更新本文档，确保代码实现、文档说明和提交记录保持一致。

## 代码注释

- 新增或修改代码时，应补充必要的中文注释。
- 注释应优先解释业务意图、边界条件、关键流程和不易直接看出的设计取舍。
- 避免添加重复代码字面含义的无效注释，例如“给变量赋值”“调用方法”等。

## Git 提交信息

提交信息应遵循 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/v1.0.0/) 规范。

推荐格式：

```text
<类型>[可选作用域]: <描述>

[可选正文]

[可选脚注]
```

常用类型：

| 类型 | 说明 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档变更 |
| `style` | 不影响代码含义的格式调整 |
| `refactor` | 既不是新增功能也不是修复缺陷的代码重构 |
| `test` | 新增或修改测试 |
| `chore` | 构建流程、依赖、脚手架等辅助变更 |

示例：

```text
feat: 添加统一响应包装能力
fix: 修复请求 ID 为空时的异常处理
docs: 更新 starter 接入说明
test: 补充全局异常处理测试
```
